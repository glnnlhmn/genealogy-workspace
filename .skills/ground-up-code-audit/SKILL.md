# Ground-Up Direct-Read Code Audit

Conduct a systematic, bottom-up architectural and quantitative code audit by reading the actual source files on disk (never relying solely on snippet previews or outdated summaries) and cross-checking every module against quantitative metrics (`gd_code_scoring`, `mypy`, `ruff`) and the 12 GDA architectural audit dimensions.

Deliver a concise **Executive Summary & Decision Points** in chat and create a **6-tab live Google Sheet** directly in Google Drive to plan, track, and batch all remediation work.

## When to Use

- The user asks for a "Ground-Up Direct-Read Audit", "full code audit", "package audit", or "architecture audit" of the GDA workspace or one of its packages (`gda.core`, `gda.io`, `gda.util`, `gda.model`, `gda.db`, `gda.repository`, `gda.entity`, `gda.engine`, `gda.manager`, `cli`, `ancestry_desk`, `system`).
- Before starting a major refactoring phase or after completing a multi-stage implementation milestone.
- Note: For quick 1-3 file peer reviews in chat without a Google Sheet, use `code-review-report`. For dedicated test suite and `conftest.py` audits, use `test-suite-audit`.

## Workspace Directory Conventions

- **Canonical Workspace Root**: `G:/My Drive/genealogy-workspace`
- **Temporary Scratch Directory**: Always use `gtemp/` (never `temp/`).
- **Staging & Intake Directory**: `download/` (ingested via `gsi`).
- **Reports Directory**: `reports/` (houses `gd_code_scoring_report.txt`).
- **Safe Backups Root**: `archive/backups_workspace/`.

## 3-Phase Audit Workflow

### Phase A: Quantitative & Structural Baseline

1. **Code Scoring Report**: Inspect or request the latest `reports/gd_code_scoring_report.txt` generated by running `python src/system/util/gd_code_scoring.py`.
2. **Static Type Baseline**: Check `mypy src` status across the target scope.
3. **Structure & Backup Hygiene**: Check directory structure (`check_structure.py`) and backup coverage (`gen_desk_backup.py --audit`) when auditing the workspace or modified domains.

### Phase B: Ground-Up Direct-Read Traversal

Read the full content of every target `.py` module on disk in strict **bottom-up dependency order** so lower-layer utilities are inventoried before evaluating whether upper layers reuse them:

1. **Tier 0 - Foundation / CIU (`gda.core`, `gda.io`, `gda.util`)**: Inventory public regexes, enums, `GDALogger`, date/time helpers, ID validators/minters, string cleaners, phonetic algorithms, and atomic/JSON I/O helpers.
2. **Tier 1 - Domain Models (`gda.model.atom` -> `gda.model.base` -> `gda.model.entity`, `xref`, `source`)**: Evaluate frozen dataclass contracts, field coercion, copy-on-write mutators, dirty flags, and serialization fidelity.
3. **Tier 2 - Database & Mappers (`gda.db.session`, `schema`, `mapper`)**: Evaluate transaction/savepoint safety, SQLite migration parity (`v001`-`v011`), row mappers, and `_MAPPER_REGISTRY` completeness.
4. **Tier 3 - Repositories & Entity Collections (`gda.repository`, `gda.entity`)**: Evaluate `QueryBuilder` usage, secondary index synchronization, tombstone/graveyard lifecycles, and repository persistence routing.
5. **Tier 4 - Engines, Managers, CLI & UI (`gda.engine`, `gda.manager`, `cli`, `ancestry_desk`, `system`)**: Evaluate graph resolvers, orchestration facades, CLI loaders, and developer tools.

### Phase C: The 12 Audit Dimensions

Evaluate every read module against all 12 dimensions and assign deterministic Audit IDs using the dimension prefix (`STR-1`, `DOC-1`, `MET-1`, etc.):

1. **`STR` - Workspace Structure & Orphaned File Hygiene**:
   - Detect stray or un-ingested files in root, `src/`, `download/`, or `gtemp/`.
   - Classify empty packages (e.g., `ancestry_desk`, `manager`, `engine` subpackages) as **Intentional Roadmap Stubs** vs. **Orphaned Legacy Directories**.
   - Flag dead/unreferenced private functions, constants, or classes.
2. **`DOC` - Documentation, `README.md` & Comment Ratio Parity**:
   - Verify line 1 module docstring `Path: <rel_path>`, summary, `Operational Role:`, `__version__ = "1.0.0+build.X"`, and sorted `__all__`.
   - Verify package `README.md` files match the actual `.py` files on disk (`gen_readme.py` parity).
   - Check `(Comments + Docstrings) / SLOC` against the ~15%-20% target (`python-code-commenting` standard).
3. **`MET` - Quantitative Code Scoring (Ruff & Radon CC/MI)**:
   - **Ruff**: 0 format or lint errors (`E, W, F, I, UP, B`), 100-column width, LF line endings.
   - **Cyclomatic Complexity (CC)**: Workspace average Grade A (`< 5.0`); review any block with `CC >= 11` (Grade C) and require helper decomposition for any block with `CC >= 21` (Grade D/E/F).
   - **Maintainability Index (MI)**: Target Grade A (`MI >= 20.0`); flag Grade B (`10.0-19.99`) and prohibit Grade C (`< 10.0`).
4. **`PY3` - Python 3.13 & Pythonic Idioms**:
   - Enforce PEP 695 generics (`class Base[T]:`, `def fn[T]():`), `StrEnum`, `X | Y` unions, `from __future__ import annotations`, and `@dataclass(repr=False, config=ConfigDict(frozen=True, extra="forbid", strict=True), kw_only=True)`.
5. **`CIU` - Foundation / CIU Reuse & Upward Promotion (DRY)**:
   - Flag upper-layer modules that compile duplicate regexes, call `logging.getLogger` instead of `GDALogger`, use raw file I/O instead of `GDAJsonIO` / `AtomicWriter`, or re-implement ID, enum, date, or string helpers.
   - Flag helpers duplicated across 2+ domain files for upward promotion into `gda.util`, `gda.core`, or `gda.model.base`.
6. **`ARC` - Architectural Boundaries & Acyclic Dependency Flow**:
   - Enforce strict one-way imports (`core/io/util` -> `model` -> `db` -> `repository/entity` -> `engine/manager` -> `cli/ui`).
   - Prohibit cross-package imports of private `_helper` symbols.
   - Verify `__init__.py` facade re-exports.
7. **`TYP` - Static Type Safety & Pydantic Contracts (`mypy`)**:
   - Require 0 `mypy` errors under `pydantic.mypy`.
   - Eliminate avoidable `# type: ignore` directives; any necessary ignore must include a specific code (`# type: ignore[override]`).
8. **`DEF` - Data Integrity, Edge Cases & Defensive Hygiene**:
   - Guard against `isinstance(True, int)` (`bool` subclass of `int`), `NaN`/`Inf` floats, and whitespace-only strings.
   - Verify immutable copy-on-write mutators touch `AuditStamp` and set `_dirty=True`.
   - Verify collection lookup methods (`__contains__`, `get`, `get_any`, `find_by_*`) return `False`/`None`/`[]` on malformed IDs rather than raising uncaught format exceptions.
9. **`SER` - Serialization, SQLite Schema & JSON Schema Parity**:
   - Verify lossless `to_dict`/`from_dict` and `to_row`/`from_row` round-trips (preserving `AuditStamp`, `Tombstone`, `Note` lists, and polymorphic subclasses).
   - Verify `_MAPPER_REGISTRY` completeness, SQLite migration column/index parity (`v001`-`v011`), and JSON schema parity (`schemas/`).
10. **`IDX` - Index & Graveyard Lifecycle Hygiene**:
    - Verify `_urn_index` and all `_by_*` secondary index buckets remain synchronized across `add`, `update`, `soft_delete`, `undelete`, and `clear`.
    - Verify `resolve_active` and hierarchy traversals use a `seen: set[ID]` cycle guard.
11. **`ERR` - Error Taxonomy & Observability**:
    - Verify all domain exceptions inherit from `GenealogyDeskError`, populate structured `details={...}` dicts, chain causes via `raise ... from err`, and log single formatted strings to `GDALogger`.
12. **`CFG` / `PRF` - Toolchain, Git Hook & Performance Alignment**:
    - Verify `pyproject.toml`, `pre_commit.py` test target routing, and `gsi.py` routing parity.
    - Flag hidden $O(N^2)$ linear scans over `_registry.values()` where a secondary index exists.

## Deliverable Format: Live 6-Tab Google Sheet + Chat Summary

### 1. Create the Live 6-Tab Google Sheet in Google Drive

Use `drive:create_file` (with `mime_type="application/vnd.google-apps.spreadsheet"`) followed by `sheets_agent:call` to create and populate a formatted 6-tab Google Sheet titled `GDA Ground-Up Code Audit - <Scope> (<YYYY-MM-DD>)`:

- **Tab 1: `Executive_Scorecard`**
  - Columns: `Domain | Files | LOC | LLOC | SLOC | Blank | Inline Comments (#) | Docstrings | (C+Doc)/SLOC % | Avg CC | CC Grade C Count | CC Grade D+ Count | MI Grade A Count | MI Grade B Count | MI Grade C Count | Mypy Errors | Ruff Status | Target Benchmark | Verdict`
- **Tab 2: `Architecture_Decisions`**
  - Columns: `Decision ID (D-01..) | Phase / Date | Architectural Tier | Decision Title | Committed Rule / Pattern | Rationale & Alternatives Rejected | Enforcement Mechanism | Status (Locked / Proposed / Superseded)`
- **Tab 3: `Module_Inventory`**
  - Columns: `Tier (0-4) | Package | File Path | __version__ | SLOC | Doc % | MI Score | MI Grade | Max CC | Max CC Symbol | README Listed? | Has __all__? | Audit Status (Clean / Action Needed)`
- **Tab 4: `Audit_Findings`**
  - Columns: `Audit ID | Severity (Blocker/High/Medium/Low) | Tier | Dimension (STR/DOC/MET/PY3/CIU/ARC/TYP/DEF/SER/IDX/ERR/CFG) | File Path | Symbol / Lines | Observation | Proposed Remediation | Related Decision ID | Assigned Batch | Status (Open/Approved/Done)`
- **Tab 5: `CIU_Promotions`**
  - Columns: `Promotion ID | Candidate Helper / Pattern | Currently Duplicated In (Files) | Target Foundation Module | Proposed Signature | Est. SLOC Saved | Assigned Batch`
- **Tab 6: `Batch_Execution_Plan`**
  - Columns: `Stage | Batch ID | Target Files (4-8 files max) | Audit IDs Resolved | Verification Gate Commands (gsi, rfmt, pytest, mypy, gd_code_scoring) | Status`

### 2. Concise Chat Executive Summary

Alongside the Google Sheet chip/link, provide in chat:
- **Overall Health Verdict**: Key metrics vs. industry and GDA standards.
- **Top Strengths to Preserve**: 3-5 architectural strengths verified on disk.
- **Top Decision Points**: 1-3 architectural choices requiring user sign-off before executing Batch 1.

## Guardrails

- **Hold on Unapproved Code Generation**: Do NOT generate refactored production files during the audit turn. Wait for the user to review the Google Sheet and approve the batch plan.
- **Sub-Batch Size Limit**: Never plan a single code-generation batch with more than 4 to 8 files so code generation never truncates.
- **No Em-Dashes or En-Dashes**: Use hyphens or colons in prose and spreadsheet cells.
